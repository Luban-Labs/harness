# Spec 模板

Task spec 的唯一格式,改自 mattpocock/skills 的 to-spec。不手写:在项目根运行 `python3 .claude/hooks/session_start.py --new-task <功能名> --kind 功能|记录`,它按下面的骨架生成 `.scratch/<功能名>/spec.md`,再逐节填写。

两种用法:
- 功能:走 interview-me 出 spec,或 owner 说「写 spec」。骨架各节都要填,只有「用户故事」可删。
- 记录:记 bug、记收不了尾的剩余项、owner 要记的小待办。生成时去掉标了 `<!-- 记录可省 -->` 的节;做着做着要改接口或出现取舍,就把类型改成功能并补齐那几节。

写法:
- 必填节没有内容写「无」,不删节;不加骨架以外的 `##` 节,别的内容放进最贴近的节。
- 「影响面」照 docs/rules/harness.md「改动的影响面」「核心判断只写一份」查出来再填,「新写或改的判断」行没有就删掉。
- 正文写现在的状态:owner 定了什么、范围变了,当场改对应的节,过时的内容直接删,历史在 git 里;进展只追加。不设篇幅上限。
- 不写具体文件路径与代码片段,它们过时得太快。例外:原型产出的片段比散文更精确地表达了一个决策(状态机、reducer、schema、类型形状),就内联到对应决策下并注明来自原型;只留决策密集的部分。「影响面」的使用方也是例外:写到模块、函数、字段或文档名,不写行号。
- 需要 Scope 时在头部加一行 `Scope: <代码目录>`,不写 `.scratch` 下的目录;开了 worktree 就加一行 `工作区: <worktree 绝对路径>`,删 worktree 时去掉。
