# 本回合 详情

## 边界与容易踩的坑
- **为什么 Claude 不按最后一条 `user` 消息切回合**:回合中途到达的 `<task-notification>`、同伴消息、压缩摘要与补充输入在日志里都是 `type == "user"`,按用户消息清零会把同一回合早先的编辑抹掉;改为以上一轮 Stop 跑完后才写的结束记录作边界。
- **为什么 DSH 以有效 `turn/start` 为准、缺边界不阻塞**:强制继续触发的 `UserPromptSubmit` 不开启新逻辑回合;缺少有效 `turn/start` 时不像 Claude/Codex 回退到首行,防止损坏或截断的日志引发误拦。
- **为什么 Claude/Codex 找不到边界时从窗口第一行算起**:尾部 8MB 窗口内没有上轮结束标记通常就是新建第一回合,若直接跳过会使首回合的判断提醒全部失效。
